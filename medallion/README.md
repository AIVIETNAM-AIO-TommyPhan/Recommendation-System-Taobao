# Medallion pipeline (Bronze -> Silver -> Gold)

A standalone data pipeline that reproduces the feature engineering used in
`Full_Training_Model.ipynb`, organized as reusable Python modules instead of
notebook cells. Run it with:

```bash
python medallion/run_pipeline.py
```

## Layers

| Layer  | Module              | Input                    | Output |
| ------ | ------------------- | ------------------------- | ------ |
| Bronze | `bronze/ingest.py`  | `input_data/*.csv(.zip)`  | `data/bronze/events/dt=YYYY-MM-DD/*.parquet` (day-partitioned impression log), `data/bronze/ad_feature.parquet`, `data/bronze/user_profile.parquet` — raw, as-is, no transformation |
| Silver | `silver/clean.py`   | Bronze                    | `data/silver/fact_events/dt=.../*.parquet`, `data/silver/dim_ad.parquet`, `data/silver/dim_user.parquet` — deduped, formatted, genuine-null handling only, no feature engineering |
| Gold   | `gold/features.py`  | Silver                    | `data/gold/training_features.parquet`, `data/gold/item_coclick_snapshot.pkl` — target encoding, historical CTR, item/user-based CF features |

`gold/snapshots.py` (product/user scoring snapshots) exists but isn't run by
`run_pipeline.py` and is gitignored — it's redundant with what the notebook
already builds inline when it needs to score, kept only as reference code.

## `data/` layout (gitignored, regenerated by `run_pipeline.py`)

```text
data/
├── bronze/
│   ├── ad_feature.parquet        # full raw ad catalog, 846,811 rows
│   ├── user_profile.parquet      # full raw user catalog, 1,061,768 rows
│   └── events/                   # impression log, partitioned by day
│       ├── dt=2017-05-05/part.parquet
│       ├── dt=2017-05-06/part.parquet
│       ├── ...
│       └── dt=2017-05-13/part.parquet
├── silver/
│   ├── dim_ad.parquet            # cleaned ad dimension (brand nulls -> "unknown")
│   ├── dim_user.parquet          # cleaned user dimension (pvalue_level/new_user_class_level nulls -> "unknown")
│   └── fact_events/              # cleaned, deduped impression log, same day partitioning as bronze
│       ├── dt=2017-05-05/part.parquet
│       ├── ...
│       └── dt=2017-05-13/part.parquet
└── gold/
    ├── training_features.parquet     # one row per impression, all engineered features + target
    └── item_coclick_snapshot.pkl     # frozen (prev_item -> candidate_item) co-click lookup, end-of-training snapshot
```

Bronze/Silver partition by day (`dt=YYYY-MM-DD/`) because the impression log
is genuinely a time series; `ad_feature`/`user_profile` don't get partitioned
since they're reference snapshots, not events.

## Relationship to `Full_Training_Model.ipynb` — read this before editing either

**This is an intentional duplication, not an oversight.** `gold/features.py`
was built by porting `Full_Training_Model.ipynb`'s feature engineering
(target encoding, domain/historical CTR, item-based/user-based CF) into
plain functions — the notebook still recomputes the same features inline,
it doesn't read from `data/gold/`. Both exist because they serve different
purposes:

| | `Full_Training_Model.ipynb` | `medallion/gold/features.py` |
|---|---|---|
| Purpose | Interactive modeling & evaluation (train models, compare AUC/Recall@K, plot feature importance, generate recommendations) | A reusable, schedulable pipeline step (e.g. a daily batch job) |
| Run by | A person, in Jupyter | `python medallion/run_pipeline.py`, unattended |
| Reads from | Raw CSVs directly | Silver (`fact_events`/`dim_ad`/`dim_user`) |

**The cost of this duplication, concretely**: earlier versions of this
notebook and the medallion pipeline briefly disagreed on how sentinel/null
values were handled (`cms_segid`'s `0` was wrongly treated as missing in
several places, copied from an assumption that turned out to be wrong once
checked against the true raw `user_profile.csv`). If you change feature
logic in one place, **check whether the same change is needed in the
other** — they are not automatically kept in sync.
